# GAP ROUND-76 — Codex CLI remote-MCP auth fields (bearer_token_env_var / env_http_headers)

## Trigger

Competitor/ecosystem research (2026-08-04): the analysis "Portable Agent Config: The MCP Gap"
(florian.bruniaux.com/blog/articles/portable-agent-config/) surveys the agent-config-portability
space and identifies the one hard unsolved gap in existing tools (it reads rulesync v9.6.3 source
to prove it): converting MCP config to/from Codex TOML **with secret handling** —
`env_http_headers`, `bearer_token_env_var`, timeouts, and approval modes are not generated by any
existing converter.

Our own Codex adapter had the same gap: those fields were silently dropped on export (no warning)
and never emitted on import.

## Official evidence

- developers.openai.com/codex/mcp — streamable HTTP server fields:
  - `bearer_token_env_var` (optional): env var name for a bearer token sent in `Authorization`;
  - `http_headers` (optional): map of header names to **static values**;
  - `env_http_headers` (optional): map of header names to **environment variable names**;
  - `auth` (optional): `oauth` / `chatgpt`.
- developers.openai.com/codex/config-reference — `mcp_servers.*.env_vars`,
  `startup_timeout_sec`, `tool_timeout_sec`, `enabled_tools`, `disabled_tools`,
  `default_tools_approval_mode`, per-tool `tools.*.approval_mode`, `experimental_environment`.

## Decisions

1. **Export (codex → portable):**
   - `bearer_token_env_var = "GITHUB_TOKEN"` → portable header
     `Authorization: "Bearer ${GITHUB_TOKEN}"` (env-var indirection is exactly what our `${VAR}`
     placeholder convention expresses — lossless, secret-free);
   - `env_http_headers = { "X-Org-Id" = "ORG_ID" }` → portable header `X-Org-Id: "${ORG_ID}"`;
   - both mappings emit an informational warning;
   - the nine client-specific per-server keys above now emit an honest
     "no portable equivalent; not exported (kept on merge)" warning instead of vanishing.
2. **Import (portable → codex):**
   - header value `Bearer ${VAR}` on `Authorization` → native `bearer_token_env_var = "VAR"`;
   - header value exactly `${VAR}` → native `env_http_headers.<header> = "VAR"`;
   - any other header value → `http_headers` (unchanged behavior);
   - merge semantics unchanged: existing entries (with their timeouts/approvals) are preserved.
3. **Redaction interaction (`stripSecrets`):**
   - values that are already pure placeholders (`${VAR}` or `Bearer ${VAR}`) carry no literal
     secret and are no longer re-redacted (previously only a `${` prefix was skipped, so
     `Bearer ${VAR}` would have been destroyed);
   - keys matching `*_env_var(s)` (e.g. `bearer_token_env_var`) hold env-var *names*, not
     secrets, and are skipped by the raw-config redaction.
4. Applies to both `codex` and `xcode-codex` (shared factory).

## Out of scope

- Generating Codex timeouts/approval modes from other clients' fields (e.g. Kimi's
  `startupTimeoutMs`): unit/semantics differ per client; both sides warn honestly and preserve
  on merge. Revisit if a portable timeout field is added to the bundle model.
