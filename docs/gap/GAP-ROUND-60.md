# GAP-ROUND-60: Nanocoder adapter (36th client)

## Candidate selection

- **Nanocoder (Nano Collective)** — selected. Open-source, local-first CLI
  coding agent (~2.3k GitHub stars, actively developed), with a documented,
  stable, file-based MCP configuration and a project-root `AGENTS.md`
  convention. Docs: https://docs.nanocollective.org/nanocoder and
  https://github.com/Nano-Collective/nanocoder (docs/configuration/
  mcp-configuration.md verified against source
  `source/config/mcp-config-loader.ts` and `source/types/config.ts`).
- **Zencoder / Zen CLI** — rejected this round: MCP servers are configured via
  IDE settings (`zencoder.mcpServers` in VS Code settings / JetBrains
  settings UI), no documented standalone CLI config file to migrate. Its
  skills live in `.agents/skills/` (already covered by codex/antigravity
  project scope) and `~/.zencoder/skills/` may become worth a follow-up if a
  standalone config file is documented.

## Verified facts (official docs + source)

- Global MCP config: `~/.config/nanocoder/.mcp.json` (Linux/XDG;
  `~/Library/Preferences/nanocoder/` on macOS, `%APPDATA%\nanocoder\` on
  Windows — AgentMove uses the home-relative `.config/nanocoder` path, same
  convention as the goose/kilo/crush adapters). Project MCP config:
  `.mcp.json` in the project root. Both use an `mcpServers` map.
- Entry schema (source `MCPServerConfig`): `transport`
  (`stdio`/`websocket`/`http`), `command`, `args`, `env`, `url`, `headers`,
  `timeout`, `alwaysAllow`, `description`, `tags`, `enabled`.
- `AGENTS.md` is read from the project root only (generated by `/init`);
  there is no user-level instructions file.
- Nanocoder "skills" are its own primitive (single-file `.md` under
  `.nanocoder/commands|agents|tools/` or a bundle under `.nanocoder/skills/`
  with `skill.yaml`) — **not** the Agent Skills SKILL.md standard.
- Env-var configs (`NANOCODER_MCPSERVERS`, `NANOCODER_CONFIG_DIR`) exist but
  are runtime overrides, not migratable files.

## Lossy mappings (all warned)

- `websocket` servers: no portable equivalent — skipped on export.
- SSE imports: no `sse` transport — emitted as `http`.
- `cwd`: not supported — dropped.
- `timeout`/`alwaysAllow`/`description`/`tags`: client-specific — warned on
  export, preserved on merge for unrelated existing entries.
- Instructions at user scope: no slot — warned, pointing at `--project`.
- Skills: nanocoder-specific skill.yaml bundle format — skipped.
- Memory: no durable store — skipped (MIF suggested).

## Deferred

- macOS/Windows platform config dirs (`~/Library/Preferences/nanocoder/`,
  `%APPDATA%\nanocoder\`) — same home-relative-path policy as other adapters.
- `NANOCODER_CONFIG_DIR` relocation — not followed (same policy as
  `VIBE_HOME`/`KIMI_CODE_HOME`).
- Nanocoder-format skills/commands/tools conversion to/from Agent Skills —
  possible future round if a faithful mapping emerges.
